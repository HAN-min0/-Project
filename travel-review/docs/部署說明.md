## 先更新 GitHub

儲存庫根目錄應有 `render.yaml`、`.github/workflows/verify.yml`、README 與 `travel-review/`。更新 `travel-review` 內的後端、前端、套件版本、環境範例與說明檔，保留此目錄結構。

`.github`、`.gitignore`、`.env.example` 也是專案檔案；請確認它們有提交。新的乾淨壓縮檔會包含這些檔案，不包含 node_modules、dist、實際資料庫與密碼。GitHub Actions 的 Verify travel review 成功後即可部署。

## 建立 Supabase 資料庫

1. 開啟 https://supabase.com/dashboard ，使用自己的帳號登入。
2. 建立一個專用專案，選 Free 與 Tokyo 或 Singapore 等接近的地區，設定資料庫密碼。此專案已建立於東京，project ref 為 `hlyjdffarxstlgvsdtul`。
3. 專案完成後按 Connect，選 PostgreSQL 的 **Session pooler** URI。
4. 將 URI 放入 Render 的 DATABASE_URL，保留 `[YOUR-PASSWORD]` 也可以；另在 Render 的 DATABASE_PASSWORD 填入資料庫密碼。程式會編碼特殊字元，不必手動修改網址。密碼只填主機環境變數，不要提交 GitHub。
5. 記下專案網址中 `/project/` 後面的 project ref，稍後填入 SUPABASE_PROJECT_REF。

不必逐張手動建表。Node.js 第一次成功啟動會執行 `server/cloud-schema.sql`，建立六張表、42 個景點與 18 筆來源快照。之後啟動不會重複加入種子資料。

如需先建立完整資料，可在專用新專案的 SQL Editor 執行 `server/cloud-bootstrap.sql`，包括建表、42 個景點與 18 筆來源快照。此專案已完成這一步。這份設定是新增專用資料表，不會把舊 SQLite 檔案上傳成 PostgreSQL。

## 建立 Render 網站

1. 開啟 https://dashboard.render.com ，登入自己的帳號並授權讀取 `HAN-min0/-Project`。
2. 建立 Blueprint，選此儲存庫，使用根目錄的 `render.yaml`。
3. 確認服務方案為 **Free**。設定已使用 Singapore、Node.js 24、根目錄 `travel-review`。
4. 在需要填寫的環境變數中，加入 DATABASE_URL、DATABASE_PASSWORD 與 SUPABASE_PROJECT_REF。
5. ADMIN_PASSWORD 由設定自動產生；之後可在服務的 Environment 查看或改為至少 16 字元的密碼。
6. 確認後建立並等待建置、資料庫初始化與健康檢查成功，使用 Render 實際提供的 HTTPS 網址。

如果採手動 New Web Service 而非 Blueprint，需設定：

| 設定 | 值 |
| --- | --- |
| Root Directory | travel-review |
| Build Command | npm ci --include=dev && npm run build |
| Start Command | npm start |
| Health Check Path | /healthz |
| Instance Type | Free |
| NODE_VERSION | 24.22.3 |
| DATABASE_URL | 你的 Supabase Session pooler URI |
| DATABASE_PASSWORD | 自己設定的 Supabase 資料庫密碼 |
| ADMIN_PASSWORD | 自訂至少 16 字元管理密碼 |
| SUPABASE_PROJECT_REF | 你的 Supabase 專案 ref |

Render 自動提供 RENDER_EXTERNAL_URL。自訂網域或其他主機則需要設定 PUBLIC_ORIGIN 為實際 HTTPS 網址，包含協定、沒有路徑。資料庫連線預設使用 TLS 並檢查憑證；需要額外 CA 時，可將 Supabase 提供的可信根憑證填入 DATABASE_CA_CERT。

本專案已在正式部署遇到 `SELF_SIGNED_CERT_IN_CHAIN`，並透過 Database Settings → SSL configuration → Download certificate 取得官方根憑證解決。將完整 PEM 內容填入 Render 的 `DATABASE_CA_CERT`，保留換行，再儲存與部署。不要關閉憑證驗證。

官方憑證下載：https://supabase-downloads.s3-ap-southeast-1.amazonaws.com/prod/ssl/prod-ca-2021.crt

此憑證為 Supabase Root 2021 CA，有效期限至 2031-04-26。已查核 SHA-256 指紋為 `80:70:25:AD:50:D4:ED:21:9D:2C:9C:7D:29:9C:00:4F:82:4E:B0:0C:F7:F6:5A:FE:F6:07:D0:7B:72:E6:CA:FA`。平台憑證更換時，請以自己專案設定頁重新下載的版本為準。

## 在哪裡看到真實資料庫

第一種是 Supabase 管理介面：登入自己的專案 → **Table Editor**。可查看 destinations、reviews、place_web_snapshots、app_meta、visitors、admin_sessions。這裡是正式儲存內容，不是程式碼中的範例清單。

第二種是網站管理頁：正式網站網址後加上 `/admin`，輸入 Render 的 ADMIN_PASSWORD。頁面會顯示「線上共用資料庫 · PostgreSQL」、實際筆數、欄位與分頁資料。此頁唯讀；資料維護可由專案擁有者在 Supabase 處理。

本機 `npm run demo` 顯示「本機驗證資料庫 · PGlite」，代表正在讀取電腦上的測試資料，尚不是 Supabase。兩種模式會在畫面上清楚標示。

## 正式 Demo 前確認

1. 先開啟正式 Render 網址，等待服務喚醒。
2. 用一般視窗新增一個景點，只填整體分數、保留空白文字心得。
3. 用另一台電腦或無痕視窗開啟同網址，更新資料後確認能看到該景點與評價。
4. 用第二個訪客留下另一筆評價，確認兩筆並存。
5. 登入 `/admin` 查看 reviews，並在 Supabase Table Editor 找到相同資料。

匿名訪客身分依瀏覽器 Cookie 保存，沒有帳號跨裝置登入。各裝置可讀共用內容，但不同裝置不會自動取得同一份評價的編輯權。

## 常見問題

找不到 package.json：確認 Render Root Directory 為 `travel-review`；本機終端機也要進入同時有 package.json 與 package-lock.json 的資料夾。

啟動顯示未設定 DATABASE_URL：在 Render Environment 填入 Supabase 連線；若目前只要在電腦驗證，使用 `npm run demo`。

網站顯示 403：確認 PUBLIC_ORIGIN 與使用中的網址相符；使用 Render 原網域時可由 RENDER_EXTERNAL_URL 自動判斷。

資料庫連不上：先確認 Supabase 專案已啟用，重新核對 Session pooler 的帳號、密碼與 URI，必要時設定可信 CA。程式不會在連線失敗時改寫暫存 SQLite。

管理密碼長度不足：在 Render → Environment → Edit，修改 `ADMIN_PASSWORD` 右側的 Value 欄，使用至少 16 個字元，接著 Save and deploy。左側 Key 應保持 `ADMIN_PASSWORD`。

舊電腦的資料沒有出現：本機 SQLite 與雲端 PostgreSQL 是不同資料庫。可先從舊版匯出個人 JSON，再依 README 使用 db:import-cloud 匯入；多人共用版備份需用 PostgreSQL 備份方式。
